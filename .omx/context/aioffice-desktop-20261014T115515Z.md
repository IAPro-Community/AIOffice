# Contexto — AIOffice Desktop

- **Pedido:** transformar o monorepo existente em aplicativo desktop instalável para Windows, macOS e Linux, com servidor e interface locais, instalações, atualizações, CI e documentação.
- **Resultado desejado:** abrir pelo app instalado, preservar os agentes/integrações e dados, receber builds e atualizações estáveis e ter evidência das plataformas realmente validadas.
- **Evidências:** raiz é monorepo npm/TypeScript; `apps/office-web` contém cliente Vite e servidor Node HTTP/SSE; `apps/office-cli` e os pacotes compartilhados são parte do projeto. `server/index.ts` atualmente inicia serviços na importação e trata SIGINT/SIGTERM. Cliente estático é servido por Fastify/HTTP local. Dados Habblaud usam `~/.habblaud`; fontes leem sessões de ferramentas em diretórios próprios.
- **Restrições:** atuar neste checkout; não clonar; não publicar/assinar/criar release; preservar todas as alterações locais existentes; sem segredos nos pacotes; build/testar apenas o que este Windows pode comprovar. Manter PolicyBroker, credenciais e integrações existentes.
- **Estado base:** branch `codex/habblaud-011-integration-20261013`; trabalho pré-existente modificado em `.omx/autopilot/habblaud-update-lifecycle/*`, `DEV/HANDOFF.md`, `DEV/VERIFY.md`, `DEV/WORKLOG.md` e `apps/office-web/client/src/ui/{update.ts,version.ts,version.test.ts}` e `shared/locales/{en,es,fr}.ts`. Preservar esses arquivos e seus diffs.
- **Decisões/hipóteses:** Electron; servidor real em processo utilitário controlado pelo main para isolamento e encerramento cooperativo; BrowserWindow com sandbox e preload mínimo; appData do SO para estado próprio, mantendo intactas as pastas de agentes e a antiga `~/.habblaud`; electron-builder + electron-updater/GitHub Releases; versão Linux AppImage atualizável e DEB com atualização manual; assinatura/notarização condicionais a segredos de CI.
- **Riscos/limites externos:** compilação macOS precisa runner macOS; publicação de atualizações seguras de Windows/macOS exige certificados e secrets; publicação não foi autorizada. node-pty é opcional/nativo e precisa ser refeito para o ABI Electron de cada runner.
- **Pontos de código:** `apps/office-web/server/index.ts`, `server/config.ts`, processo de build do servidor; nova aplicação desktop sob `apps/office-desktop/`; scripts raiz, lockfile npm, workflow GitHub Actions, documentação `DEV/` e README.
